## Данные и подготовка

В `Student_Performance.csv` содержатся 10 000 строк и 5 признаков; целевая переменная — `Performance Index`. Значения `Extracurricular Activities` преобразованы по правилу `Yes → 1`, `No → 0`. Пропусков нет. Обнаружены 127 повторяющихся строк, которые сохранены: без идентификаторов наблюдений нельзя установить, являются ли совпадения ошибочным дублированием. Оценка ниже относится к исходному набору данных без удаления этих строк.

В `german.csv` содержатся 1 000 строк и 20 признаков. Файл прочитан с разделителем `;`, первый столбец `Creditability` использован как целевая переменная. Пропусков и повторяющихся строк нет. Числовые коды категориальных признаков сохранены без дополнительного кодирования; это упрощает эксперимент, но вводит числовой порядок категорий, влияющий на линейную модель и расстояния KNN.

Оба набора разделены на обучение и тест в отношении 80/20 с `random_state=42`: 8 000/2 000 строк для регрессии и 800/200 для классификации. Для кредитных данных применено `stratify=target`: в обучении 240 объектов класса 0 и 560 класса 1, в тесте — 60 и 140 соответственно. Для каждого набора свой `StandardScaler` обучен только на обучающих признаках; тест преобразован с уже найденными параметрами. Целевые переменные не масштабировались. Все классификаторы получили одно и то же разбиение и одинаково подготовленные признаки.

## Гипотезы и эксперименты

Обе собственные модели реализованы через пакетный градиентный спуск на NumPy: на каждой эпохе используются все обучающие объекты, веса и смещение первоначально равны нулю. Для линейной модели минимизируется MSE: при ошибке `e = Xw + b − y` градиенты равны `2Xᵀe/n` и `2mean(e)`. Для логистической модели минимизируется бинарная кросс-энтропия (BCE): при `p = sigmoid(Xw + b)` градиенты равны `Xᵀ(p − y)/n` и `mean(p − y)`. Сигмоида вычисляется с разделением положительных и отрицательных аргументов, BCE — через `logaddexp`. Истории содержат потери на обучении после каждого обновления параметров. Порог бинарного решения собственной модели равен 0.5.

Основной запуск использует параметры контракта: для линейной модели `learning_rate=0.05`, `epochs=800`, для логистической — `learning_rate=0.1`, `epochs=1000`. Проверена гипотеза, что уменьшение шага до 0.01 замедлит сходимость при том же числе эпох. Дополнительные запуски сравнивались только по обучающим потерям; подбор параметров по тестовым метрикам не проводился.

Обучающая MSE линейной модели:

| Эпоха | Шаг 0.05 | Шаг 0.01 |
| ---: | ---: | ---: |
| 1 | 2777.91081029 | 3292.53904732 |
| 10 | 421.08187973 | 2290.59522043 |
| 100 | 4.16973833 | 64.57037373 |
| 800 | 4.16973585 | 4.16973585 |

Обучающая BCE логистической модели:

| Эпоха | Шаг 0.1 | Шаг 0.01 |
| ---: | ---: | ---: |
| 1 | 0.68246165 | 0.69206186 |
| 100 | 0.49215185 | 0.61354075 |
| 500 | 0.48215984 | 0.51600101 |
| 1000 | 0.48213176 | 0.49232668 |

Гипотеза подтверждается на приведённых контрольных эпохах: меньший шаг даёт более медленное снижение потерь. Линейные модели к 800-й эпохе достигают практически одинаковой MSE; логистическая модель с шагом 0.01 за 1 000 эпох сохраняет более высокую BCE.

Для сравнения использованы `DecisionTreeClassifier(random_state=42)` и `KNeighborsClassifier(n_neighbors=5)`. Дополнительно запущен `LogisticRegression(max_iter=1000, random_state=42)`: эта готовая модель предусмотрена стартовым файлом и полем `logistic_regression` контракта. Поэтому JSON содержит отдельно `own_logistic` и три готовые модели. Собственные реализации не используют готовые линейные модели sklearn.

## Выводы

Собственная линейная модель успешно снижает обучающую MSE и достигает тестовой MSE 4.08262840. При выбранном масштабировании шаг 0.05 приводит к близкому к итоговому значению уже к 100-й эпохе.

Собственная логистическая модель превосходит дерево и KNN по всем пяти измеренным тестовым метрикам. По Accuracy её преимущество составляет 8.5 процентного пункта перед деревом и 5 перед KNN. Возможное объяснение — пригодность линейной границы для этого набора и чувствительность KNN к расстояниям между числовыми кодами категорий. Причины различий отдельно не проверялись; по одному разбиению нельзя доказать переобучение дерева или общее превосходство модели.

У собственной и готовой логистических моделей совпали Accuracy, Precision, Recall и F1, а ROC-AUC собственной модели ниже примерно на 0.000476. Собственная модель обучается без регуляризации, готовая — с регуляризацией по умолчанию и другим алгоритмом оптимизации. Это возможные причины небольшого расхождения вероятностей; их вклад экспериментально не разделялся.

## Воспроизводимость

Использованы Python 3.14.3, NumPy 2.4.4, Pandas 3.0.2 и scikit-learn 1.9.1. Файлы `Student_Performance.csv`, `german.csv`, `linear_models.py` и каталог `grader_contracts` должны находиться в исходной структуре репозитория. Из его каталога выполнить:

```bash
python linear_models.py
```

Команда повторяет подготовку данных, обучение основных и дополнительных моделей, сохраняет основные тестовые результаты в `experiment_results.json` и печатает метрики и контрольные значения потерь. Разбиения фиксированы значением 42, начальные параметры собственных моделей нулевые; случайное состояние готовых логистической модели и дерева также зафиксировано. Настройки моделей, число эпох и подготовка данных заданы в коде. Контракты не изменялись. При другой версии библиотек возможны небольшие численные отличия.
